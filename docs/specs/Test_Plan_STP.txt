Verification strategy for the Rust video add-on host, add-on SDK, and playback pipeline.

2. Test Objectives
Verify that the application satisfies the SRD requirements for video add-on installation, browsing, search, resolution, playback, auth, data persistence, and diagnostics.
Verify that untrusted add-ons cannot escape the sandbox, exceed quotas, access unauthorized domains, or read secrets without grants.
Verify that the add-on SDK remains compatible across releases through contract tests and fixture add-ons.
Verify that player integration is stable enough for MVP playback scenarios on target desktop platforms.
Verify that release builds are reproducible enough to package, sign, and support with clear diagnostics.
2.1 In scope and out of scope
In scope
Out of scope for this STP
Rust core, add-on host, SDK, data/auth, player adapter, UI flows, repository/package validation.
Testing illegal content sources or DRM bypass workflows.
Direct URL and HLS playback smoke/regression tests.
Full codec certification across every possible video/audio/subtitle format.
Desktop targets: Linux, macOS, Windows.
Mobile, smart-TV, console, and embedded-device certification.
Fixture add-ons and mock services.
Reliability of third-party services outside controlled integration environments.

3. Test Strategy
Level
Purpose
Primary tools/approach
Unit tests
Validate pure Rust domain logic, manifest parsing, permissions, player state, error mapping, and schema migrations.
cargo test; property tests for parsers and state transitions.
Component tests
Validate crates with mocks: add-on host, network wrapper, data repositories, auth service, player backend trait.
Mock HTTP server, mock player, temporary DB, test keychain abstraction.
Contract tests
Validate SDK ABI/types and fixture add-ons against host versions.
rvah-testkit; golden JSON/WASM fixtures; compatibility matrix.
Integration tests
Validate end-to-end flows across UI/core/add-on/player with controlled services.
Headless UI harness where possible; mock service; fake player or mpv smoke mode.
Playback tests
Validate source loading, controls, subtitles, progress, errors, and resume.
Known-good media fixtures, local HTTP server, HLS test manifest.
Security tests
Validate sandbox isolation, permission enforcement, signature rejection, redaction, quota/timeouts.
Malicious fixture add-ons, fuzz inputs, static scanning, dependency audit.
Performance tests
Validate startup, browse latency, search aggregation, runtime quotas, and player-start timing.
Benchmarks, controlled network latency, synthetic large catalogs.
Manual exploratory
Validate living-room style navigation, visual polish, error comprehensibility, and real-world service flows.
Scripted charters, diagnostics export, release candidate builds.

5. Test Data and Fixtures
Fixture
Purpose
catalog_echo
Returns deterministic nested directories, media items, artwork references, pagination, and metadata.
resolver_static
Returns direct MP4, HLS, expired URL, unsupported protocol, bad header, and subtitle variants.
auth_device_code
Exercises successful auth, expired code, denied code, token refresh, and revocation.
bad_permissions
Attempts unauthorized domain access, secret access, storage overflow, and local file access.
slow_addon
Sleeps, loops, allocates memory, and delays network to validate quotas and cancellation.
malformed_manifest
Missing required fields, invalid versions, unsupported SDK range, duplicate ID, invalid permissions.
large_catalog
Generates 10,000 items with paging to validate performance, memory use, and UI virtualization.
mock_media_server
Serves MP4, HLS, subtitles, redirects, 404/500 responses, range requests, and throttled bandwidth.

6. Entry and Exit Criteria
Gate
Criteria
Test entry
Build compiles; unit tests pass; manifest schema frozen for the test cycle; fixture add-ons generated; known blockers triaged.
MVP exit
All Priority 0 and Priority 1 tests pass; no open critical/high security defects; playback smoke passes on target OSes; diagnostics export verified.
Release candidate exit
Regression suite green; package signing verified; dependency/license/security scan reviewed; performance budgets met or exceptions approved.
Add-on SDK exit
Contract tests pass for all supported SDK versions; breaking changes documented; simulator and examples updated.

Expected result

Host rejects package and records diagnostic without modifying installed state.

TC-ADD-008
Uninstall add-on with data retention selected.

10. Defect Severity and Release Rules
Severity
Definition
Release rule
Critical
Host crash, data loss, sandbox escape, secret leak, unsigned code execution, or repeatable playback corruption.
Must be fixed before any release.
High
Major feature unusable, add-on lifecycle broken, auth broken, security boundary weakened, or player unusable on target OS.
Must be fixed or formally waived for non-public builds only.
Medium
Workaround exists; affects limited providers or non-core flows.
May ship with owner approval and documented known issue.
Low
Cosmetic, copy, minor diagnostics, or developer-tool issue.
May ship if backlog item exists.

11. Manual Exploratory Charters
Provider discovery: install three fixture add-ons, compare browsing/search clarity, and verify provider errors are understandable.
Living-room flow: complete browse-to-playback using keyboard/remote-like navigation only.
Failure recovery: disconnect network during browse and playback, then reconnect and verify retry behavior.
Credential hygiene: authenticate, export diagnostics, inspect logs, revoke account, and uninstall provider.
Upgrade rehearsal: install old build, create data, upgrade to release candidate, verify migrations and add-on compatibility.
